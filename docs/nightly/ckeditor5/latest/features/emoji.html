Emoji

Contribute to this guideShow the table of contents

The emoji feature lets you insert emojis into the document from the editor toolbar or while writing the content. The emojis are pulled from the CDN to lessen the editor load.

Since there is a large number of emojis, they have been conveniently divided into several categories for easier use, such as “Smileys & Expressions” or “Objects.” You may also search for a specific emoji using the search field.

Demo

Copy link

Use the emoji toolbar button in the editor below to open a panel with a table of selectable emojis. You may also trigger the emoji UI while writing the content by typing the pre-configured : marker followed by at least two letters of desired emoji name. Then, you can either choose which emoji to insert from the suggestion list or select the Show all emoji... option to open the full panel. The marker must be preceded by a space to work.

There is an option to set the skin tone of the emojis next to the search field, too.

The selected emoji category and skin tone are remembered by the feature, so next time you invoke the panel, you can quickly insert an emoji of similar type.

Overview of Emojis

Emojis are small digital images or icons used to express emotions, ideas, or concepts in electronic communication. They originated in Japan in the late 1990s, with the first set created by Shigetaka Kurita. Since then, emojis have evolved into a global communication tool, becoming an essential part of online and mobile messaging. Emojis convey non-verbal cues, adding emotional context or visual interest to text-based conversations. They help to bridge the gap left by the absence of facial expressions and tone in digital communication.

Examples of Common Emojis

  • 😊 Smiling Face: Used to convey happiness, friendliness, or gratitude. This emoji is often used in conversations to express positivity.
  • ❤️ Red Heart: Represents love, affection, or appreciation. It is widely used in romantic and platonic contexts.
  • 😂 Face with Tears of Joy: Indicates laughter or something funny. It is one of the most popular emojis, often used to show amusement or that something is humorous.
  • 😢 Crying Face: Represents sadness, disappointment, or sympathy. It can be used to express empathy or convey sorrow.
  • 👍 Thumbs Up: Used to show approval, agreement, or to indicate that everything is good or okay.
  • 🔥 Fire: Often used to signify something hot, trendy, or impressive. It is also used in contexts related to passion or excitement.

The Impact of Emojis on Communication

Emojis have revolutionized digital communication, adding nuance and clarity to messages. They help users express emotions in a way that text alone may not capture. For instance, a simple sentence like "I'm excited" might feel flat without an emoji, but adding an emoji like 🎉 (party popper) or 😄 (grinning face) helps to convey enthusiasm more effectively. Emojis also shape culture and trends, as their meanings can evolve, and new emojis are regularly introduced to reflect societal changes.

This demo presents a limited set of features. Visit the feature-rich editor example to see more in action.

Installation

Copy link

After installing the editor, add the feature to your plugin list and toolbar configuration:

import { ClassicEditor, Emoji, Mention } from 'ckeditor5';

ClassicEditor
	.create( {
		licenseKey: '<YOUR_LICENSE_KEY>', // Or 'GPL'.
		plugins: [ Emoji, Mention, /* ... */ ],
		toolbar: [ 'emoji', /* ... */ ],
		emoji: {
			// Configuration.
		}
	} )
	.then( /* ... */ )
	.catch( /* ... */ );

		}
	} )
	.then( /* ... */ )
	.catch( /* ... */ );
Copy code
Note

The emoji feature requires the mentions feature to be installed to work properly.

The emoji plugin consists of two sub-plugins:

  • EmojiMention – Adds support for triggering the emoji UI dropdown while writing the content when you type a pre-configured : marker followed by at least two letters of the desired emoji name.
  • EmojiPicker – Registers the UI button component, which opens a panel with a table of selectable emojis.

You can freely choose how to load the feature: either as a whole (as shown in the example above) or select one of the sub-plugins if you need only one of the ways of inserting emojis into the document.

Unsupported contexts

Copy link

The emoji autocompletion triggered by the : marker is automatically disabled inside code blocks. Typing : inside a code block will insert the character as plain text without triggering the emoji suggestions. The toolbar emoji picker button remains available regardless of the cursor position.

Configuration

Copy link

The feature can be configured via the config.emoji object.

  • dropdownLimit – the number of items to appear in the emoji dropdown.

    ClassicEditor
	.create( {
		// ... Other configuration options ...
		emoji: {
			dropdownLimit: 5
		}
	} )
	.then( /* ... */ )
	.catch( /* ... */ );
    Copy code

  • skinTone – the initial skin tone for the emojis that support skin tones.

    ClassicEditor
	.create( {
		// ... Other configuration options ...
		emoji: {
			skinTone: 'medium'
		}
	} )
	.then( /* ... */ )
	.catch( /* ... */ );
    Copy code

  • definitionsUrl – the URL to the emoji definitions file. The URL should return a JSON array with emoji definitions specified by the EmojiDefinition interface. This option is ignored if the definitions setting is provided.

    Warning

    If the definitionsUrl is not provided, the feature will fetch the emoji definitions from the CKEditor 5 CDN.

    ClassicEditor
	.create( {
		// ... Other configuration options ...
		emoji: {
			definitionsUrl: 'https://example.com/emoji-definitions.json'
		}
	} )
	.then( /* ... */ )
	.catch( /* ... */ );
    Copy code

  • definitions – the emoji definitions passed directly to the editor, as an array of EmojiDefinition items. If this option is provided, the feature does not download anything, and the definitionsUrl and version settings are ignored. Read more in the Bundling the emoji database section.

    ClassicEditor
	.create( {
		// ... Other configuration options ...
		emoji: {
			definitions
		}
	} )
	.then( /* ... */ )
	.catch( /* ... */ );
    Copy code

  • version – the emoji database version. By default, version 16 is used. This option is ignored if the definitionsUrl or definitions setting is provided.

    ClassicEditor
	.create( {
		// ... Other configuration options ...
		emoji: {
			version: 15
		}
	} )
	.then( /* ... */ )
	.catch( /* ... */ );
    Copy code

  • useCustomFont – if you customize the emoji availability and appearance. It that case, it is highly recommended to disable the filtering mechanism because it uses a font built-in to your system.

    ClassicEditor
	.create( {
		// ... Other configuration options ...
		emoji: {
			useCustomFont: true
		}
	} )
	.then( /* ... */ )
	.catch( /* ... */ );
    Copy code

Emoji availability and appearance

Copy link

The availability of the emoji depends on the operating system. Different systems will have different Unicode support. You may decide to lower the number of newer emoji by setting a lower version of Unicode of the emoji repository (CKEditor 5 hosts v15 and v16) or by providing a custom emoji repository using the definitionsUrl. This way, the users with newer systems will not be able to use newer emojis. Keep in mind that this only affects the editor feature. A user will still be able to use the native emoji insertion methods. The availability may also increase with the usage of a custom font.

If you want to standardize the appearance of emoji accross operating systems, please consider using an external font in your integration, such as Noto Color Emoji. In the setup make sure to:

  1. Set the font-family for the content, this way the emoji in the editable will use the custom font. For example:

    body {
	font-family: 'Lato', 'Noto Color Emoji', sans-serif;
}
    Copy code

  2. Update the --ck-font-family variable, so that emoji in the picker and mention will use the custom font.

    :root {
	--ck-font-family: Helvetica, Arial, Tahoma, Verdana, 'Noto Color Emoji';
}
    Copy code

  3. Update the editor configuration by adding the emoji.useCustomFont option.

    {
	// ... Other configuration options ...
	emoji: {
		useCustomFont: true
	}
}
    Copy code

Emoji source

Copy link

The database of English emoji is loaded by default from our CDN. Make sure that your CSP rules are correctly set up.

If you do not want to use our distribution and prefer to self-host emoji, you can use the definitionsUrl option. You can download the data directly from the package mentioned above or from our CDN, and place it under a static assets URL, for example:

  1. Download the latest emoji database from https://cdn.ckeditor.com/ckeditor5/data/emoji/16/en.json, or download version 15 for older Unicode versions.
  2. Place the downloaded file in your application’s assets folder, for example public/emoji/en.json. The specific location may vary depending on your framework and setup.
  3. Update the configuration option definitionsUrl to point to the URL of your assets, for example: https://example.com/emoji/en.json.

You can prepare your own database with a different emoji set, but it must have an identical structure as ours. Otherwise, the Emoji feature will not work.

Bundling the emoji database

Copy link

The feature downloads the emoji database with a network request. Some pages do not allow it, for example, when their Content Security Policy only accepts connections to the page’s own origin and you cannot host the file there. In such a case, you can bundle the database with your application and pass it in the definitions option:

import definitions from './emoji/en.json';

ClassicEditor
	.create( {
		// ... Other configuration options ...
		emoji: {
			definitions
		}
	} )
	.then( /* ... */ )
	.catch( /* ... */ );
Copy code

The database has several hundred kilobytes, so bundling it makes your application bigger. To keep it out of the main bundle, load it as a separate chunk before you create the editor:

const { default: definitions } = await import( './emoji/en.json' );
Copy code
Warning

Your bundler turns the imported JSON file into a JavaScript file, so the CSP script-src rule applies to it. If you use a native JSON module in the browser without a bundler (import ... with { type: 'json' }), the connect-src rule applies to it instead, just like to a network request.

When the definitions option is provided, the feature ignores the definitionsUrl and version options. If you set them as well, the editor logs the emoji-repository-redundant-options warning.

Marker conflicts

Copy link

The emoji feature uses the : marker that opens a panel with a table of selectable emojis. If you use the mentions or merge fields features, they can also show UI panels by pressing a pre-configured key. Those keys may conflict with the emoji feature. In such a case, the EmojiMention plugin will not integrate the autocompletion mechanism.

To prevent conflicts, make sure that the mention’s marker and merge field’s prefix configuration options are not defined as :.

Troubleshooting

Copy link

If you are experiencing issues with the emoji feature in CKEditor 5 and the emoji-repository-empty is displayed in the console, it may be due to missing system support for emoji fonts or problems loading the emoji repository. Below are some common issues and their solutions.

No emoji font installed

Copy link

Problem:
The system does not have an emoji font installed, preventing the emoji feature from rendering emoji correctly.

Solution:
To use the emoji feature, install an emoji font on your operating system:

  • macOS: Apple Color Emoji
  • Windows: Segoe UI Emoji
  • Linux: Noto Color Emoji (or an alternative like Twemoji)

Once installed, restart your browser and reload the editor.

Server error when loading the emoji repository

Copy link

Problem:
The request to load the emoji repository was completed, but the server returned an error (such as 404 Not Found, or 500 Internal Server Error).

Solution:

  • Ensure the emoji repository URL is correct and accessible.
  • If using a custom emoji repository, verify that it is properly configured.

Network issues preventing the emoji repository from loading

Copy link

Problem:
The emoji repository could not be loaded due to a network issue, CORS restriction, or blocked request.

Solution:

  • Verify that the URL is correct and accessible.
  • Check your internet connection.
  • If applicable, update your Content Security Policy (CSP) settings to allow connections to the emoji repository.
  • If you cannot change the CSP settings, bundle the emoji database with your application.

For more details on configuring CSP, see the Content Security Policy guide.

Empty bundled emoji database

Copy link

Problem:
The definitions option is provided, but the feature does not show any emoji.

Solution:

  • Make sure that the option contains a non-empty array, not a promise or a module object. Wait for the dynamic import() to finish before you create the editor.
  • Make sure that the definitions have the same structure as the database hosted on the CKEditor 5 CDN.

By following these steps, you should be able to resolve common issues with the emoji plugin in CKEditor 5. If problems persist, check your browser console for additional error messages or consult the CKEditor 5 GitHub repository for support.

Common API

Copy link

The EmojiPicker plugin registers the UI button component ('emoji') and the command ('emoji') that allows opening the emoji picker UI.

Note

We recommend using the official CKEditor 5 inspector for development and debugging. It will give you tons of useful information about the state of the editor, such as internal data structures, selection, commands, and many more.
