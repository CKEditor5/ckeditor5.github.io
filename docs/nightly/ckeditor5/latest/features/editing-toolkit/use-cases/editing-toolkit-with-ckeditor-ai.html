Editing Toolkit with CKEditor AI

Show the table of contents

Use CKEditor AI Document Processing to edit document content from your own interface or agent. CKEditor AI processes the document HTML, and the Editing Toolkit compares the result with the original so users can review and apply the changes in the editor.

Demo

Copy link

Choose an action to send the document and an editing instruction to CKEditor AI. The Editing Toolkit compares the result with a snapshot and lists the changes in the panel next to the editor. Preview a change, then apply it directly, record it as a Track Changes suggestion, or reject it. The proposed edits do not change the document until you apply them. When to use this approach

Copy link

Use this approach when you already use CKEditor AI and are building your own AI features or agent workflows. The Document Processing endpoint lets your agent delegate document editing to the CKEditor AI agent.

  • Send an editing instruction and document HTML to CKEditor AI. Retained element IDs in the response let Compare match elements across versions.
  • Let users review and pick individual changes in the Proposed changes UI before they reach the document.
  • Mix in built-in CKEditor AI features where they fit, for example Quick Actions for selected text, while the main conversation stays in your interface.

For a built-in chat interface in the editor, see the AI Chat guide. To build AI features with your own agent and model, see the custom chat implementation guide, which uses Coauthor.

How it works

Copy link

  1. The user picks an action in your application or asks for something in your chat.
  2. Your application takes a snapshot through the Editing Toolkit. It includes the document HTML, with IDs on structural elements, and the editor state needed to apply the differences later. The user can keep editing while the request runs.
  3. Your application sends the request and snapshot content to your agent.
  4. Your agent calls the Document Processing endpoint of the CKEditor AI service with the prompt and document HTML.
  5. The service returns the processed HTML. Retained element IDs let the comparison match elements across versions.
  6. Your agent returns the processed HTML to your application, together with any reply your interface shows the user.
  7. Your application passes the processed HTML and original snapshot to the Editing Toolkit to compute grouped changes for review.
  8. The toolkit displays the proposed changes without applying them to the document.
  9. The user applies a change directly, records it as a Track Changes suggestion, or rejects it.

What you need

Copy link
  • The DocumentCompare and ProposedChanges plugins from the Editing Toolkit, loaded in the editor with a license key. See the Comparing documents and Proposing changes guides for setup and API examples.
  • Access to the CKEditor AI service and a token with the AI permissions. The CKEditor AI integration guide covers the setup, and the deployment options guide covers Cloud and on-premises.
  • The Track Changes integration if users should be able to record changes as suggestions.
